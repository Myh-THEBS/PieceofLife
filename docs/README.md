# 项目文档

这里的文档是**代码注释的替代品** —— 本项目代码注释极少，设计意图、约定与历史都记录在这些文件里。
如果你（或你的 AI 助手）要接手这个仓库，建议按下面的顺序阅读。

| # | 文档 | 定位 | 时效 |
|---|---|---|---|
| 1 | [project_context.md](project_context.md) | **权威**：当前架构、模块职责、页面状态机、活跃决策日志（D01~D52） | 随开发更新 |
| 2 | [hotfix_record.md](hotfix_record.md) | 修复账本：每次 Bug 的根因、排查过程与改动 | 随开发更新 |
| 3 | [开发者总结报告.md](开发者总结报告.md) | 项目基础信息、文件结构、开发规则 | v2.0 时期快照 |
| 4 | [项目重构报告.md](项目重构报告.md) | 从 Java（原项目 TheArchite）重构为 Kotlin 的过程与结果 | v2.0.1 时期快照 |

## 阅读建议

- **想知道"现在是什么样"** → 读 1
- **想知道"某个行为为什么是这样写的"** → 先在 2 里搜关键词（按日期记录，含排查过程），再回到 1 查决策日志 `D##`
- **想了解项目从哪来** → 读 3、4（历史文档，部分内容已过时，不要当作现状）

## 维护约定

- `project_context.md` 与 `hotfix_record.md` 是**活文档**：每次功能开发或 Bug 修复后同步更新
- 决策日志采用 `D##` 编号连续维护，新决策追加在表尾，已修订的条目直接改写并在描述里注明修订原因
- 历史快照类文档（3、4）**不再回填**，保留原貌，避免与 1 产生两份互相矛盾的"现状"
