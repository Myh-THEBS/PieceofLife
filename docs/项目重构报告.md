## 一、项目概述

### 1.1 重构源起

**原项目 TheArchite** 是一个使用纯 Java 开发、运行在 Android 10 (API 29) 上的个人日志与任务管理 APP。存在严重的架构和技术债务问题：

| 问题 | 影响 |
|:-----|:-----|
| 无架构模式 | Activity 承担 UI、业务、数据存取全部职责 |
| 纯 Java 代码 | ~4000 行，难以扩展和维护 |
| 原生 SQLite (`SQLiteOpenHelper`) | 手写 SQL，无 ORM，UI 线程查库有 ANR 风险 |
| `SharedPreferences` | 手动管理 XML 读写，类型不安全 |
| 130+ 散落 PNG | 无精灵图管理，资源膨胀 |
| 双线性插值放大 | 像素风格画面模糊 |
| 无 ViewModel | 配置变更时状态丢失 |
| 无协程 | 所有操作在 UI 线程 |
| `onUpgrade` 为空实现 | 数据库升级即丢失数据 |

### 1.2 重构目标

1. **Java → Kotlin 全量迁移**
2. **MVVM 架构落地**（ViewModel + Repository）
3. **Room 数据库替代 SQLiteOpenHelper**
4. **DataStore 替代 SharedPreferences**
5. **协程替代原始线程**
6. **精灵图体系重建**（Sprite Sheet + 最近邻缩放）
7. **编辑器完全重写**（富文本 + 属性解析 + 触发器插入）
8. **新增 5 大功能模块**（文件日志/数据统计/标签管理/任务提醒/用户头像）

## 四、关键设计决策

### 4.1 数据流架构

```
Repository-centric 模式

子 Activity → Repository (直接 DB 操作) → setResult → MainActivity.refresh()
                                                      ↕
                                              MainViewModel.refresh { state -> }
```

### 4.2 精灵图体系

```
SpriteDef 定义坐标 → SpriteLoader 加载+缓存 → ImageView.setImageBitmap()
  ├── setButton(view, resId, frame, downFrame) → 双帧触摸动画
  ├── setIcon(view, index) → 单帧精灵
  └── background48(index) → 九宫格背景 Drawable
```

**按钮双帧约定**：偶数帧 = 弹起，奇数帧 = 按下。`setButton()` 默认取下一帧。

### 4.3 导航保存协议

```
btnTool2（信息按钮）→ 检测变更 → 无变更直接打开 LogInfoActivity
                                → 有变更弹窗确认 → 静默保存 → 打开 LogInfoActivity
LogInfoActivity 返回 → MODE_DOCUMENT：重新加载 .md 文件内容
                     → MODE_PICTURE：从 DB 重载 + 文件系统重载缩略图
```

### 4.4 备份系统

```
ZIP 包结构：
├── manifest.json       ← 用户配置 + file_manifest
├── pieces_of_life.db   ← Room 数据库
├── images/             ← 全部图片（含 avatar.jpg）
└── documents/          ← 全部文档

进度：ProgressDialog（ProcessBar 精灵图）
缺失文件：导入后写 HINT 日志告知
```

### 4.5 通知系统

```
PieceOfLifeApp.onCreate() → 通知渠道 (CHANNEL_ID_QUEST_REMINDER)
QuestReminderReceiver.onReceive()
  → 重新调度下一次提醒
  → 统计 today + thisWeek 到期任务
  → 构建通知 → NotificationManagerCompat.notify()
```
